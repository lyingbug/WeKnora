# 插件开发指南

WeKnora 的插件是**一个 YAML 文件**，不是 Go 代码。把文件放进插件目录，运行中的服务器就多一项能力；删掉文件，能力就消失。不需要重新编译，不需要重启，也不需要 fork 这个仓库。

这条约束是整个设计的出发点。一个需要写 Go、重新构建、重新部署才能扩展的机制不是插件系统，它是**有组织的硬编码**——只有能发版的人才能参与。把扩展的单位变成文件，意味着任何能读懂厂商 API 文档的人都能接入一个新服务。

## 一分钟上手

在插件目录里新建 `my-search.yaml`：

```yaml
apiVersion: weknora/v1
kind: websearch
id: my-search
name: 我的搜索源

config:
  - id: api_key
    type: string
    label: API Key
    required: true
    secret: true

runtime:
  type: http
  request:
    method: POST
    url: https://api.example.com/search
    headers:
      Authorization: Bearer ${config.api_key}
    body:
      query: ${input.query}
      limit: ${input.max_results}
  response:
    items: data.results
    fields:
      title: title
      url: link
      snippet: summary
```

保存即生效。设置页会出现"我的搜索源"，并根据 `config` 自动渲染出一个带掩码的 API Key 输入框。删除文件，它就从列表里消失。

## 插件目录

| 来源 | 位置 | 说明 |
|---|---|---|
| 内置 | 编译进二进制 | 随版本发布，开箱可用 |
| 用户 | `WEKNORA_PLUGIN_DIR`，默认 `./plugins` | 被监听，改动即时生效 |

两个来源相互独立：用户目录里的错误不会影响内置插件。用户目录里放一个 `id` 相同的文件会**覆盖**内置插件，这是定制官方集成的方式。

## 清单格式

### 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `apiVersion` | ✓ | 固定 `weknora/v1` |
| `kind` | ✓ | 能力域，如 `websearch` |
| `id` | ✓ | 域内唯一，配置里引用的就是它 |
| `name` | ✓ | 界面显示名 |
| `description` | | 一句话说明 |
| `docURL` | | 你所依据的厂商文档链接 |
| `config` | | 需要运维填写的配置 |
| `runtime` | ✓ | 怎么执行 |

### config：配置字段

一处声明，同时用于**校验**和**表单渲染**。你不需要写任何校验代码，设置页也不会出现插件根本不接受的字段。

```yaml
config:
  - id: api_key          # 用 ${config.api_key} 引用
    type: string         # string | int | float | bool | enum
    label: API Key
    help: 在控制台的密钥页面获取
    placeholder: sk-...
    required: true
    secret: true         # 掩码显示，不回传，日志脱敏
  - id: region
    type: enum
    default: cn
    options:
      - value: cn
        label: 中国
      - value: us
        label: 美国
  - id: timeout_ms
    type: int
    min: 1000
    max: 60000
    default: 15000
```

`required` 和 `default` 互斥：必填就不该有默认值。

### runtime: http —— 声明式集成

绝大多数集成都是同一个形状：拼一个 HTTP 请求，从 JSON 回复里取值。这个形状写成数据，就不用写代码。

```yaml
runtime:
  type: http
  request:
    method: POST              # 默认 GET
    url: ${config.base_url}/search
    timeout: 20s              # 默认 15s
    query:                    # URL 查询参数
      q: ${input.query}
    headers:
      Authorization: Bearer ${config.api_key}
    body:                     # JSON 请求体，结构化
      query: ${input.query}
      options:
        深度: ${config.depth}
  response:
    items: data.results       # 结果数组的路径
    errorPath: error.message  # 可选：HTTP 200 但回复里带错误的情况
    fields:
      title: title            # 相对于单条结果的路径
      url: link
      snippet: content
```

路径用 [gjson](https://github.com/tidwall/gjson) 语法，支持 `data.results`、`highlights.0` 这样的写法。

### 表达式

只有一种语法：`${命名空间.键}`。没有函数、没有运算、没有条件判断。插件文件是部署方手写的输入，所以表达式层是一张查找表而不是一门语言——里面没有可以被利用的东西，也没有需要调试的东西。

| 命名空间 | 内容 |
|---|---|
| `config` | 该插件声明的配置字段 |
| `input` | 由能力域定义，`websearch` 提供 `query`、`max_results`、`include_date` |

有两种替换模式，**这个区分是格式安全的关键**：

- 整个值就是一个表达式 → 保持原本类型。`limit: ${input.max_results}` 发出去的是 JSON 数字 `5`。
- 表达式嵌在文本里 → 结果是字符串。`Bearer ${config.api_key}` 拼成一个请求头。

因为是**类型化替换**而不是文本拼接，一个包含引号或大括号的搜索词不可能破坏 JSON 请求体，更不可能注入。如果用文本模板，这就成了清单作者的问题；现在它根本不可能发生。

引用一个不存在的可选配置会解析为空，此时**该查询参数或 body 字段会被整个省略**，所以你不需要写条件判断。

### runtime: native —— 逃生舱

有些集成确实没法用数据描述：DuckDuckGo 免费档没有 JSON 接口，只能解析 HTML；Google 走的是官方 Go SDK。这类插件仍然要写清单（这样它照样出现在目录里、照样有设置表单），但 `runtime` 指向一个编译进二进制的实现：

```yaml
runtime:
  type: native
  native: duckduckgo
```

**逃生舱是刻意做得不好用的**：加一个 native 插件仍然需要改 Go 并发版，而这正是文件格式想消除的成本。如果一个新集成想用它，第一个该问的问题是——声明式运行时是不是缺了什么能力，补上之后所有后来者都能受益。

## 错误怎么报

手写文件一定会写错，所以加载器按"一个坏文件只损失一个插件"设计：

- 解析失败、字段拼错、表达式引用了没声明的配置——都在**加载时**报出来，不会等到某次请求才炸。
- 坏文件被跳过并单独记录原因，其余插件照常工作。
- 上一版继续生效，直到新版完整准备好。

严格解析意味着 `nmae: X` 这样的拼写错误会直接报错，而不是安静地让那个设置失效。

## 能力域

一个域定义 `input` 里有什么、`response.fields` 该映射哪些名字。目前只有 `websearch`。

### websearch

**输入**：`query`（搜索词）、`max_results`（条数）、`include_date`（是否需要发布时间）

**输出字段**：

| 字段 | 必需 | 说明 |
|---|---|---|
| `title` | | 标题 |
| `url` | ✓ | 链接。没有链接的结果会被丢弃 |
| `snippet` | | 摘要 |
| `content` | | 正文全文（如果厂商返回） |
| `published_at` | | RFC 3339 时间戳 |

## 新增一个能力域

需要三样东西：

1. **定义域的契约**：`input` 提供什么、`response.fields` 期望什么名字，写成常量。
2. **把内置清单装进注册表**：用 `go:embed` 嵌入你的 `plugins/*.yaml`，调 `plugin.LoadFS`。
3. **消费方走注册表**：`reg.Configure(kind, id, raw)` 校验配置，再 `entry.Invoke(...)` 执行。

参考 `internal/infrastructure/web_search/plugin.go`，整个绑定层不到 200 行。
